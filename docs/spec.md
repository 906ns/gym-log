# 機能仕様

## 0. 前提

| 項目 | 内容 |
| --- | --- |
| 利用者 | 1人（本人のみ）。アカウントの概念なし |
| 端末 | iPhone（ホーム画面に追加した standalone Web App）。PC は開発用 |
| 利用場所 | ジム（記録）と自宅（体重入力、振り返り） |
| 通信 | 前提にしない。初回読み込み後はオフラインで全機能が動く |
| 器具 | 全種目がピン選択式（セレクタライズ）マシン。表示重量がそのまま記録値 |

---

## 1. 中核となる利用フロー

ジムでの1セットあたりの操作を、最短で **3タップ** に収める。

```
アプリを開く
  └─ 進行中セッションがあれば、そのままセッション画面が開く（タップ0）
       └─ 種目カードを開く（タップ1）        ← 前回の全セットが見える
            └─ 前回記録の行をタップ（タップ2） ← 重量とレップが入力欄に入る
                 └─「記録」をタップ（タップ3）
```

重量を変える場合は、この間に `+` / `−` を必要回数タップする。

この3タップ以上を要求する導線は設計ミスとして扱う。

## 2. 画面

### 2.1 ホーム

アプリ起動時の画面。ただし進行中のセッションがある場合はセッション画面へ自動遷移する。

構成要素:

1. **体重カード**
   - 最新の体重と測定日、前回測定からの差分（`68.4 kg / 9月14日 / −0.4`）。
   - 体脂肪率が記録されていれば併記する。
   - タップで体重入力モーダルを開く。
   - 記録が1件もないときは「体重を記録する」とだけ表示する。
2. **主ボタン**
   - 進行中セッションなし → 「今日のトレーニングを開始」
   - 進行中セッションあり → 「トレーニングを続ける」＋経過時間
   - 同じ日に終了済みのセッションがある場合も「今日のトレーニングを開始」を出す
     （1日2回行くことがあるため、日付で1件に制限しない）。
3. **直近の履歴**（5件）
   - 日付、曜日、種目数、総ボリューム（kg）、コンディションメモの先頭1行。
   - タップでそのセッションの詳細（読み取り専用の一覧）を開く。
   - 履歴が0件のときは「まだ記録がありません」とだけ表示する。

### 2.2 セッション

トレーニング中の画面。この画面にいる間だけ Screen Wake Lock を取得する。

構成要素:

1. **ヘッダー**: 日付、セッション開始からの経過時間、「終了」ボタン。
2. **種目カードのリスト**: そのセッションで記録した種目が、記録した順に並ぶ。
3. **「種目を追加」ボタン**: 種目ピッカーを開く。
4. **固定フッター**: 最後にセットを記録した時刻からの経過時間（休憩時間）。

#### 種目カード

閉じた状態では、種目名と今日のセット数・最大重量だけを表示する。
開いた状態で以下を表示する（同時に開くのは1種目のみ。他は自動で閉じる）。

```
┌─────────────────────────────────┐
│ チェストプレス                       │
│                                 │
│ 前回 9/12                        │
│   45 kg × 10   ↩                │
│   45 kg × 9    ↩  「最後きつい」    │
│   40 kg × 10   ↩                │
│                                 │
│ 今日                             │
│   1  45 kg × 10   ✎             │
│                                 │
│ ┌─────────────────────────────┐ │
│ │  −  [  45  ] kg  +          │ │
│ │  −  [  10  ] 回  +          │ │
│ │        [ 記録する ]          │ │
│ └─────────────────────────────┘ │
│                                 │
│ セッティング: シート4、背もたれ2      │
└─────────────────────────────────┘
```

- **前回**: 直近にこの種目を記録したセッションの全セット。セット単位のメモがあれば併記。
  各行に「この値を入力欄に入れる」ボタン（`↩`）を置く。
- **今日**: このセッションで記録済みのセット。行タップで編集、右端のアイコンでメモ編集。
- **入力欄の初期値**:
  1. 今日すでに1セット以上記録していれば、直前のセットと同じ値
  2. なければ、前回セッションの第1セットと同じ値
  3. どちらもなければ空
- **セッティング**: 種目マスタの `setup_note`。空なら行自体を出さない。
  ここもタップで編集できる（ジムでその場で書けることが重要）。

#### 種目ピッカー

- 既定の並びは **直近に使った順**。五十音順・登録順は使わない。
- 部位（胸 / 背中 / 肩 / 脚）でのフィルタを上部に置く。
- そのセッションで既に記録済みの種目には印を付けるが、選択は可能にする
  （後から戻ってセットを追加することがあるため）。
- 最下部に「種目を新規作成」。名前と部位だけ入れれば即使える簡易フォーム。

#### 休憩の経過時間（固定フッター）

- 表示値は `Date.now() - 直近の sets.recorded_at`。
- **カウンタを加算する実装にしない**。`setInterval` で 1 秒ごとに再計算する。
  バックグラウンドでタイマーがスロットリングされても、復帰時に正しい値になる。
- 種目ごとの `default_rest_seconds` を超えたら色を変える（`--brass` → `--steel`）。
- そのセッションで1セットも記録していない間は非表示。
- 開始・停止ボタンは置かない。セットの記録が起点になる。

### 2.3 設定

1. **種目マスタ**: 一覧、名前・部位・重量刻み・目標休憩秒数・セッティングメモの編集、
   並べ替え、アーカイブ（使わなくなった種目を隠す。削除ではない）。
2. **データ**: JSON エクスポート、JSON インポート（全置換）、データ保持状態の表示。
3. **表示**: 体脂肪率の入力欄を出すかどうか、既定の目標休憩秒数。
4. **情報**: アプリのバージョン、Service Worker のキャッシュ世代、
   保存件数（セッション数 / セット数 / 体重記録数）。

## 3. 機能の詳細

### 3.1 セッション

- 「開始」で `sessions` に1件作成し、`started_at` に現在時刻を入れる。
- 「終了」で `ended_at` を入れる。確認ダイアログを出す。
- **セットが0件のまま終了した場合は、そのセッションを論理削除する**
  （誤タップで空のセッションが履歴に溜まるのを防ぐ）。
- 進行中セッション = `ended_at === null` かつ `deleted_at === null` のもの。
  複数存在してはならない。存在した場合は最新のものを使い、他は `ended_at` を
  最終セットの時刻で埋めて閉じる（アプリを強制終了した場合の復旧処理）。
- コンディションメモはセッション画面のヘッダーからいつでも編集できる。

### 3.2 セットの記録

- 記録時に `recorded_at` を入れる。`order` はその種目内での連番（1から）。
- 重量は 0.25 kg 刻みまで受け付ける（小数第2位で丸める）。0 kg を許可する
  （自重種目を後から追加した場合のため）。上限 500 kg。
- レップは 1〜100 の整数。
- 直前のセットと完全に同じ値でも記録できる（同一判定で弾かない）。
- セットの削除は論理削除。削除後、同じ種目内の `order` は振り直さない
  （`recorded_at` 順に表示するので `order` は表示に使わない。同期時の衝突を避けるため）。

### 3.3 前回記録の取得

「前回」= 現在のセッション以外で、その種目を記録した最新のセッション。

1. `sets` の `[exercise_id, recorded_at]` インデックスを降順にたどる。
2. `deleted_at !== null` の行は飛ばす。
3. `session_id` が現在のセッションと同じ行は飛ばす。
4. 最初に出会った `session_id` を「前回のセッション」とし、
   その `session_id` を持つ行を集め終わったら打ち切る。

3か月経っても計算量が増えないこと。全件走査は書かない。

### 3.4 体重

- 1日1件。同じ `date` に入力した場合は上書き（upsert）。
  朝と夜で2件残ると推移が使えなくなるため。
- 入力は日付（既定は当日）、体重（必須）、体脂肪率（任意）。
- 前回値をプリフィルする。体重は前日から大きく動かないため、
  差分の入力に近い操作になる。
- 過去日付の入力・修正を許可する（入れ忘れた日を後から埋められるように）。
- 差分表示は「直前の測定日」との比較。7日前との比較は v1 では出さない。

### 3.5 メモ

3種類あり、置き場所で役割が違う。

| 種類 | 保存先 | 用途 |
| --- | --- | --- |
| セッションメモ | `sessions.condition_note` | 筋肉痛、寝不足、ジムの混雑など、その日全体の状況 |
| セットメモ | `sets.note` | フォームの崩れ、あと1回いけた、握力が先に落ちた など1セット固有 |
| セッティングメモ | `exercises.setup_note` | シート位置、ピン穴の番号など、毎回変わらない情報 |

- セットメモは入力を必須にしない。フォーカスを自動で当てない。
  記録済みのセット行の右端アイコンからインライン展開して入力する。
- メモがある行には印を出す。
- セットメモは前回記録の表示にも出す。ここが本来の目的
  （数字だけでは、その8回が正しい8回だったか判断できない）。

### 3.6 エクスポート / インポート

- エクスポート: 全ストアの全レコード（論理削除済みを含む）を1つの JSON にして
  `gym-log-YYYY-MM-DD.json` としてダウンロードする。
- 形式は `docs/data-model.md` の転送形式に従う。
- インポート: **全置換**。既存データを消してから投入する。
  確認ダイアログで「現在の記録がすべて置き換わります」と明示する。
  マージはサーバー同期を実装するときに作る。
- インポート前に検証する。`schema_version` が想定外、必須キーの欠落、
  型の不一致があれば何も書き込まずに中断する。部分的に適用しない。
- 論理削除済みレコードもエクスポートに含める。除外すると、
  復元後に削除の事実が失われ、将来の同期で復活するため。

### 3.7 オフラインとキャッシュ

- Service Worker は App Shell（HTML / CSS / JS / manifest / icons / seed json）を
  precache し、リクエストに対して cache-first で応答する。
- キャッシュ名にバージョンを含め（`gym-log-v1`）、`activate` で旧世代を削除する。
- **ファイルを更新したらキャッシュバージョンを上げる**。上げ忘れると端末に
  古いコードが残り続ける。この手順は README に書く。
- ユーザーデータはキャッシュの対象外（そもそもネットワークに出ない）。

## 4. 空の状態と失敗時の表示

| 状況 | 表示 |
| --- | --- |
| 記録が0件 | 「まだ記録がありません」＋開始ボタン |
| 体重が0件 | 「体重を記録する」 |
| 前回記録がない種目 | 「この種目は初回です」 |
| IndexedDB が開けない | 「データを保存できません。プライベートブラウズを使っている場合は通常モードで開いてください」 |
| インポートの検証失敗 | 何が問題かを具体的に出す（「schema_version が 2 です。このアプリは 1 を読み込みます」） |
| Wake Lock 非対応 | 何も表示しない |

エラー文は謝らない。何が起きて、どうすれば良いかだけを書く。

## 5. 計算式

`js/lib/calc.js` に純関数として置く。

- **1セットのボリューム** = `weight × reps`
- **セッション総ボリューム** = そのセッションの全セットのボリューム合計（論理削除を除く）
- **推定1RM** = Epley 式 `weight × (1 + reps / 30)`。`reps === 1` のときは `weight`。
  他の式（Brzycki など）に変えると過去の数値と比較できなくなるため、式を固定する。
  表示は小数第1位まで。
- **種目の今日の最大重量** = そのセッション内の `weight` の最大値
- **前回比** = 今日の推定1RM − 前回セッションの推定1RM（それぞれ最大値で取る）

推定1RM は v1 では種目カードの折りたたみ表示に小さく出すだけで、
専用の画面やグラフは作らない。
