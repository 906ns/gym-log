# v1.2 UI 仕様 — アプリシェルの導入

v1.1 の実装を前提とした差分仕様。UI のみの変更で、**データモデルとビジネスロジックは
一切変更しない**。`AGENTS.md` の禁止事項（ビルドツール、フレームワーク、npm 依存、
CDN、`innerHTML`、物理削除）はすべて有効。

`docs/ui.md` のトークン（炭色の背景、スチールの無彩色、真鍮色のアクセント1色）と
ダークテーマは維持する。ライトテーマは作らない。

---

## 0. 何を変えるのか

現状は3つの画面を丸ごと入れ替えている。これはウェブページの構造で、
画面ごとに何がどこにあるか変わるため、操作を都度探すことになる。

アプリは骨格が固定されていて、中身だけが差し替わる。この差が
「アプリらしさ」の正体で、色や角丸や影ではない。以下はその骨格を作る変更。

---

## 1. アプリシェル

画面全体を3層に分ける。上と下は常に同じ位置にあり、中央だけが切り替わる。

```
┌───────────────────────────────┐
│ ヘッダー（48px + safe-area-top）│ ← 常設
├───────────────────────────────┤
│                               │
│         コンテンツ              │ ← ここだけ切り替わる
│      （唯一スクロールする）      │
│                               │
├───────────────────────────────┤
│ ミニバー（進行中のみ・44px）      │ ← 条件付き
├───────────────────────────────┤
│ タブバー（56px + safe-area-bot）│ ← 常設
└───────────────────────────────┘
```

- `body` はスクロールさせない（`overflow: hidden`）。スクロールするのは
  コンテンツ層だけ。これをやらないと、スクロール時にヘッダーやタブバーが
  ずれて動いてページのように見える。
- コンテンツ層に `-webkit-overflow-scrolling: touch` と
  `overscroll-behavior: contain` を指定する。端で引っ張ったときに
  ページ全体が動くのを防ぐ。

### ヘッダー

- 左: 画面タイトル（18px / 600）。階層が1つ深い画面では戻るアイコンに変わる。
- 右: その画面固有のアクションを最大1つ。無ければ空。
- 背景は `--bg`、下端に `--line` の1px。影は付けない。

### タブバー

3つ。アイコン（24px）とラベル（11px）を縦に積む。

| タブ | 内容 |
| --- | --- |
| ホーム | 体重、カレンダー、今週の状況、開始ボタン |
| 履歴 | セッションの一覧（日付降順）。日付タップで詳細 |
| 設定 | 種目マスタ、単位、バックアップ |

- 選択中は `--brass`、非選択は `--muted`。
- タップ領域は高さいっぱい（56px）を確保する。アイコンだけを領域にしない。
- `padding-bottom: env(safe-area-inset-bottom)` を入れる。
- タブの切り替えにスライドアニメーションを付けない。即座に差し替える。

「履歴」は新規の画面。v1.1 ではホームに直近5件を出していたが、それは
カレンダーに置き換わるので、一覧はここに移す。

---

## 2. セッション画面はタブバーの上に乗せる

セッション画面（記録中）は**タブではなく、全画面で上に重ねる**。
タブバーは隠す。

理由は、タブバー・休憩バー・入力エリアの3つを画面下端に積むと、
390px 幅の画面で入力エリアが押し上げられ、3タップで記録するという
中核の動線が壊れるため。

- ヘッダーの左を「閉じる」（下向きシェブロン）にする。戻るではなく閉じる。
- 閉じてもセッションは終了しない。ミニバーから復帰できる。
- 開くときは下から上へ 200ms でスライドイン。閉じるときは逆。
  この1箇所だけ方向のあるアニメーションを使う。

---

## 3. 進行中セッションのミニバー

セッションが進行中で、かつセッション画面を閉じているときだけ、
タブバーの真上に薄いバーを出す。

```
┌───────────────────────────────┐
│ ● 記録中  45:12    3種目 8セット │
└───────────────────────────────┘
```

- 高さ 44px。背景 `--surface-2`、上端に `--line` の1px。
- 左端に `--brass` の小さな丸。点滅させない。
- タップでセッション画面に戻る。
- 時間は `started_at` からの経過。1秒ごとに再計算する。

これは音楽アプリのミニプレイヤーと同じ役割で、「何かが進行中である」ことを
どの画面にいても示す。アプリらしさに一番効く要素。

---

## 4. リスト行の統一形

現状は場所ごとに行の作りが違う。以下の1種類に統一する。

```
┌───────────────────────────────┐
│ [icon]  タイトル           値 › │
│  32px   サブテキスト            │
└───────────────────────────────┘
```

| 要素 | 指定 |
| --- | --- |
| 行の高さ | 最小 56px（2行のときは 68px） |
| アイコン枠 | 32 × 32px、`--r-ctl` の角丸、`--surface-2` の背景 |
| アイコン | 20px、`currentColor`、色は `--steel` |
| タイトル | 17px / 500 / `--text` |
| サブテキスト | 13px / 400 / `--muted` |
| 右の値 | 15px / `--muted`、`tabular-nums` |
| シェブロン | 16px / `--muted`。遷移する行にだけ置く |
| 区切り | 左側をアイコン幅 + 余白ぶんインデントした `--line` の1px |

区切り線を左端まで引かない。アイコンの右端から始める。これだけで
リストが「作られている」ように見える。

適用先: 種目マスタ、履歴の一覧、設定の各項目、種目ピッカー。

---

## 5. セクションヘッダーと件数バッジ

リストのまとまりごとにヘッダーを置く。

```
胸                              2
─────────────────────────────────
[icon] チェストプレス         セレクタライズ ›
[icon] ペックフライ           セレクタライズ ›
```

- ヘッダーは 13px / 600 / `--muted`。**英大文字化・全角大文字化しない**。
- 右端に件数。数字だけを置き、「件」は付けない。
- ヘッダーはスクロール時に上端で固定する（`position: sticky; top: 0`）。
  背景は `--bg` を敷いて下の行が透けないようにする。

---

## 6. シートと遷移

| 種類 | 動き |
| --- | --- |
| シート（種目ピッカー、履歴、編集） | 下から 200ms でスライドイン。背景を 40% 暗くする |
| 階層遷移（設定 → 種目編集） | 右から 200ms でスライドイン。戻るときは逆 |
| タブ切り替え | アニメーションなし |
| ダイアログ（確認） | 中央にフェードイン 120ms |

- シートは `<dialog>` の `showModal()` を使う（v1 の方針を維持）。
- シートの上端に幅 36px / 高さ 4px のグラバー（`--line`）を置く。
  下方向スワイプで閉じる機能は実装しない。閉じるボタンで閉じる。
  スワイプ判定は縦スクロールと競合し、誤操作の原因になる。
- `prefers-reduced-motion: reduce` で全て無効にする。

---

## 7. 押下のフィードバック

タップした瞬間に何かが変わること。遅延があると反応しなかったように感じる。

- 全ての操作要素に `:active` の状態を定義する。
  背景を `--surface-2` に、または `opacity: .7`。
- `transition` は `background-color 80ms` まで。押下だけは即座に。
- `touch-action: manipulation` を全ての操作要素に指定する
  （ダブルタップズームの 300ms 遅延を消す）。
- `-webkit-tap-highlight-color: transparent` で青い矩形を消す。
  ただし消すなら `:active` を必ず定義すること。消しただけだと無反応に見える。

---

## 8. 余白のグリッド

全ての余白を 4px の倍数にする。既存のトークン（`--sp-1` 〜 `--sp-6`）を使い、
`13px` や `18px` のような中途半端な値を書かない。

- 画面の左右余白は `--sp-4`（16px）に統一する。
- セクション間は `--sp-5`（24px）。
- 行内の要素間は `--sp-3`（12px）。

揃っていない余白は、他がどれだけ作り込まれていても雑に見える。

---

## 9. アイコン

インライン SVG で自作する（CDN 禁止のため）。24 × 24、線幅 1.5、
`stroke="currentColor"`、`fill="none"`、端は丸め。

必要なもの（これ以上増やさない）:

ホーム、履歴（時計）、設定（歯車）、追加（＋）、閉じる（下シェブロン）、
戻る（左シェブロン）、進む（右シェブロン）、検索、メモ（鉛筆）、削除（ゴミ箱）、
体重（グラフ）、種目の部位4種（胸・背中・肩・脚）。

部位アイコンは人体図を描こうとしない。単純な図形で区別が付けばよい。
凝ると線が潰れて読めなくなる。

`<symbol>` として `index.html` に一度だけ定義し、`<use>` で参照する。
同じ SVG を何度も書かない。

## 10. 空の状態

説明文ではなく、次の操作への誘導にする。

| 場所 | 表示 |
| --- | --- |
| 履歴が0件 | アイコン（薄く）+「最初のトレーニングを記録する」+ 開始ボタン |
| 体重が0件 | 「体重を記録する」（カード全体がボタン） |
| 前回記録なし | 「この種目は初回です」 |
| 検索結果0件 | 「該当する種目がありません」+「種目を新規作成」 |

アイコンは `--line` 相当の薄さで 48px。イラストは描かない。

---

## 11. やらないこと

- ライトテーマ
- カンバン形式・横スクロールするレイアウト（390px に入らず、汗ばんだ手での
  片手操作で誤操作が起きる）
- 全要素を同じ角丸・同じ影のカードに切る作り（階層が消える）
- 影の使用（面の区別は明度差と罫線で作る）
- ラベルの英大文字化・全角大文字化
- ボタン文字への矢印付加
- 中黒で連結したメタ情報
- 自動再生されるアニメーション、スクロール連動のフェードイン
- 下方向スワイプでのシート閉じ、横スワイプでの削除

---

## 12. 実装順序

1. アプリシェル（ヘッダー・コンテンツ・タブバーの3層構造、`body` のスクロール禁止）
2. 「履歴」タブの新設と、ホームからの一覧の移動
3. セッション画面を全画面の重ねる形に変更
4. 進行中セッションのミニバー
5. リスト行の統一形を作り、既存の全リストに適用
6. セクションヘッダーと件数バッジ
7. アイコンの `<symbol>` 定義と差し替え
8. 遷移・押下フィードバック・余白グリッドの統一
9. 空の状態

各フェーズの終わりで `npm test` が通り、コミットすること。
