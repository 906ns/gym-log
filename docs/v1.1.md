## 2. 単位（kg / lb）

### 2.1 保存と表示の分離

**保存は常に kg**。表示だけを切り替える。

- `sets.weight` と `body_weights.weight` は kg のまま。単位カラムを増やさない。
- 換算は `1 lb = 0.45359237 kg`（国際ポンドの定義値）を使う。近似値を使わない。
- kg で保持する値は小数第4位で丸める。これより粗く丸めると lb で入力した値を
  lb に戻したときに一致しなくなる。
- 表示時の丸めは、kg は 0.25 刻み、lb は 0.5 刻み。

この方式にする理由は、単位を切り替えても過去の記録が同じ重さを指し続けることです。
レコードごとに単位を持たせると、集計のたびに混在した単位を足すことになり、
総ボリュームや推定1RMが壊れます。

### 2.2 設定

- `meta.weight_unit`: `'kg' | 'lb'`。既定は `'kg'`。アプリ全体の表示単位。
- `exercises.display_unit`: `'inherit' | 'kg' | 'lb'`。既定は `'inherit'`。
  種目ごとの上書き。マシンの表記が種目によって違う場合に使う。
- 体重は常に `meta.weight_unit` に従う（種目ごとの上書きは適用しない）。

### 2.3 実装

`js/lib/units.js` を新規追加する。純関数のみ。

```js
export const LB_IN_KG = 0.45359237;

export function lbToKg(lb)            // → kg（小数第4位で丸め）
export function kgToLb(kg)            // → lb（丸めなし）
export function roundForDisplay(v, unit)  // kg: 0.25刻み / lb: 0.5刻み
export function formatWeight(kg, unit)    // → { value: number, label: 'kg'|'lb' }
export function parseWeightInput(text, unit) // → kg。不正値は null
```

集計（ボリューム、推定1RM）は必ず kg で計算し、表示の直前に換算する。
lb に換算してから足し込む実装にしない。丸め誤差が累積する。

### 2.4 テスト（必須）

- `lbToKg` → `kgToLb` の往復で、1.0 から 500.0 まで 0.5 刻みの全ての lb 値が
  元の値に一致すること。
- `kgToLb` → `lbToKg` の往復で、1.0 から 300.0 まで 0.25 刻みの全ての kg 値が
  元の値に一致すること。
- `parseWeightInput` が全角数字、空文字、負値、`'1.2.3'`、範囲外を `null` にすること。
- 単位を切り替えてもセッション総ボリュームの kg 換算値が変わらないこと。

## 3. 増減幅の切替と長押し

### 3.1 問題

v1 は `exercises.weight_increment` の固定値（5kg）だけだった。
1kg 刻みにしたい場合、40kg から 60kg まで動かすのに20回タップすることになる。
刻みを細かくするほど操作回数が増えるという構造を先に解く必要がある。

### 3.2 刻みの切替

重量の入力行の直下に、刻みを選ぶセグメントを置く。

- kg のとき: `1` / `2.5` / `5` / `10`
- lb のとき: `1` / `2.5` / `5` / `10`

選択値は種目ごとに保存する。次に同じ種目を開いたとき同じ刻みで始まる。

- `exercises.increment_kg`: 既定 5
- `exercises.increment_lb`: 既定 5

kg と lb で別々に持つ。マシンのピンの刻みは単位系によって違うため、
換算した値を使うと選べない重量が出る。

レップ側の刻みは常に 1 で、切替を置かない。

### 3.3 長押しでの連続増減

`+` / `−` は長押しで連続的に値が動くこと。

- 押してから 400ms 後に連続増減を開始する。
- 開始直後は 120ms 間隔。1.5 秒経過後は 60ms 間隔に加速する。
- 指を離した時点で停止する。`pointerup` / `pointercancel` / `pointerleave` の
  すべてで停止すること。取りこぼすと値が動き続ける。
- 連続増減中は下限・上限（重量 0〜500kg、レップ 1〜100）で停止する。
  上限に達しても増減を継続しない。

### 3.4 数値の直接入力

数値そのものをタップしたら、その場でキーボード入力に切り替わること。
40kg から 85kg のように大きく動かすときに、増減ボタンを使わせない。

- 重量: `inputmode="decimal"`、レップ: `inputmode="numeric"`
- `type="text"` + 自前バリデーション（v1 の方針を維持）
- フォーカス時に既存の値を全選択する。手で消させない。
- 確定は「記録する」ボタンまたは `Enter`。フォーカスが外れた時点でも値を反映する。

## 4. 入力エリアの寸法統一

現状は重量とレップの入力行の寸法が揃っていない。以下に統一する。

```
┌─────────────────────────────────────┐
│  ┌────┐  ┌───────────────┐  ┌────┐  │
│  │ −  │  │     45.0   kg │  │ +  │  │   ← 行1: 重量
│  └────┘  └───────────────┘  └────┘  │
│           [ 1 ][2.5][ 5 ][10 ]      │   ← 刻み切替（重量のみ）
│  ┌────┐  ┌───────────────┐  ┌────┐  │
│  │ −  │  │      10    回 │  │ +  │  │   ← 行2: レップ
│  └────┘  └───────────────┘  └────┘  │
│                                     │
│  ┌───────────────────────────────┐  │
│  │          記録する              │  │
│  └───────────────────────────────┘  │
└─────────────────────────────────────┘
```

| 要素 | 指定 |
| --- | --- |
| `−` / `+` ボタン | 52 × 52px。両行で同一。位置も左右で揃える |
| 数値フィールド | 両行で同一の幅（`flex: 1` で同じコンテナ内に置く）、高さ 64px |
| 数値の文字 | 44px / 600 / `tabular-nums`。**重量とレップで同一**。中央揃え |
| 単位ラベル | 13px / `--muted`。数値の右に置く。`kg` `lb` `回` で幅を固定（右端揃え） |
| 刻みセグメント | 高さ 40px、4等分。選択中のみ `--brass` の枠線 |
| 記録するボタン | 高さ 56px、横幅いっぱい |
| 行間 | `--sp-3`（12px） |

数値の文字サイズを揃えるのは、視線が縦に動くときに基準が変わらないようにするためです。
片方が小さいと、どちらが重量でどちらがレップか都度読み直すことになります。

### 入力エリアの固定表示

開いた種目カード内で、入力エリアがカード下端に固定されること。
前回記録や今日のセットが増えてもスクロールで隠れない。

- 実装は `position: sticky; bottom: 0`。カード外に出さない（画面固定の休憩フッターと
  重なるため、休憩フッターの高さ分の `bottom` を確保する）。
- 別の種目カードを開いたら、その種目の入力エリアに切り替わる。

## 5. 自己ベスト（PR）

### 5.1 定義

種目ごとに3種類を持つ。論理削除済みと `is_warmup` のセットは除外する。

| 名称 | 定義 |
| --- | --- |
| 最大重量 | `weight` の最大値（レップ数は問わない） |
| 推定1RM | Epley 式 `weight × (1 + reps / 30)` の最大値 |
| 単セット最大ボリューム | `weight × reps` の最大値 |

Epley 式は v1 から変更しない。式を変えると過去の数値と比較できなくなる。

### 5.2 保存しない

PR は保存せず、種目カードを開いた時に算出する。

理由は、キャッシュを持つと更新漏れとサーバー同期時の不整合という2種類のバグが
増えることです。1種目あたりのセット数は週3回 × 3セットで年間約150行、
複合インデックスで1種目分だけ走査するので算出コストは問題になりません。
数千行を超えて体感で遅くなったら、その時点でキャッシュを検討する。

### 5.3 表示

- 開いた種目カードの「前回」の上に1行:
  `自己ベスト 50.0 kg × 8 / 推定1RM 63.3 kg`
- 記録したセットが3種類のいずれかを更新したら、そのセット行に `自己ベスト` の印を
  付ける（`--brass`）。音・バイブ・通知は出さない。
- 更新の判定は、そのセットを記録する**直前**の記録との比較で行う。
  同一セッション内で2セット連続して更新した場合、両方に印が付く。
- 初回のセット（過去の記録が0件）には印を付けない。全部が自己ベストになり、
  印が意味を失う。

## 7. 休憩の目標秒数の調整

セッション中に、画面下端の休憩表示をタップすると小さな操作パネルが開く。

- `−15秒` / `+15秒` のボタンと、現在の目標秒数の表示。
- 変更は開いている種目の `default_rest_seconds` に保存する。
  次回同じ種目を開いたときに反映される。
- 下限 0 秒（0 のときは色の変化をしない）、上限 600 秒。

Hevy も15秒単位での調整を持っており、単位はこれに合わせる。

## 8. セットの編集・削除

v1 では論理削除の仕組みだけがあり、UI がなかった。

- 「今日」のセット行をタップすると編集シートが開く。
- 内容: 重量、レップ、メモ、`削除` ボタン。
- スワイプ削除は実装しない。理由は、ライブラリなしでの横スワイプ判定は
  縦スクロールとの競合が起きやすく、誤操作でセットが消えるのが最も避けたい失敗だからです。
- `削除` は確認ダイアログを経由し、`deleted_at` を立てる。物理削除しない。
- 削除後も `order` は振り直さない（v1 の方針を維持）。

## 9. 過去日付でのセッション作成

記録を忘れた日を後から埋められるようにする。

- ホームの主ボタンの下に「過去の日付で記録する」を置く。
- 日付を選んでセッションを作成する。`started_at` はその日の 12:00 とする
  （実際の時刻が不明なため、休憩時間の算出に使わない値を入れる）。
- 過去日付のセッションでは休憩の経過時間を表示しない。意味を持たないため。
- 進行中セッションが既にある場合は、過去日付のセッションを作れない。
  先に現在のセッションを終了させる。

体重カードと主ボタンの間に置く。

- 当月の日付グリッド。セッションがあった日に `--brass` のドットを付ける。

- 日付タップでその日のセッション詳細へ。
- 連続日数は出さない（理由は第1節の表を参照）。

## 11. データモデルの変更（`SCHEMA_VERSION` → 2）

### 追加するフィールド

```js
// exercises
increment_kg: number,      // 既定 5
increment_lb: number,      // 既定 5
display_unit: 'inherit' | 'kg' | 'lb',  // 既定 'inherit'

// meta（キー追加）
weight_unit: 'kg' | 'lb'   // 既定 'kg'
```

### 削除するフィールド

`exercises.weight_increment` は `increment_kg` に置き換える。
移行時に既存の値を `increment_kg` にコピーし、`increment_lb` は 5 を入れる。

### マイグレーション

`onupgradeneeded` に `if (from < 2)` のブロックを追加する。既存の
`if (from < 1)` のブロックは書き換えない。

- `exercises` ストアをカーソルで走査し、各レコードに新フィールドを追加する。
- IndexedDB のリクエストのみを使い、`fetch` や外部 Promise を待たない。
  versionchange トランザクションが閉じる。
- `meta.schema_version` を 2 に更新する。
- 転送形式（エクスポート）の `schema_version` も 2 にする。
  インポート時は `1` と `2` の両方を受け付け、`1` の場合は読み込み時に
  上記と同じ補完を行う。**過去のバックアップが読めなくなってはいけない。**

### シードファイル

`data/exercises.seed.json` を差し替える（別途提供）。
`weight_increment` が `increment_kg` / `increment_lb` / `display_unit` に
置き換わっている。`id` は v1 と同一の固定値のまま変えないこと。
