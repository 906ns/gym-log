# v1.2 追補 — テーマ切り替え（ダーク / ライト）

`docs/v1.2-ui.md` と同じ実装パスで対応する。UI のみの変更で、
データモデルとビジネスロジックは変更しない。

---

## 1. 3つのモード

設定 → 表示 にセグメントを置く。

| 値 | 動作 |
| --- | --- |
| `system` | OS の設定に追従する（既定値） |
| `dark` | 常にダーク |
| `light` | 常にライト |

`system` のときは `matchMedia('(prefers-color-scheme: dark)')` の
`change` イベントを購読し、OS 側の変更に即座に追従する。
`dark` / `light` のときは購読を解除する。

---

## 2. 適用の仕組み

`<html>` 要素の `data-theme` 属性で切り替える。

```css
:root { /* ダークの値 */ }

@media (prefers-color-scheme: light) {
  :root:not([data-theme="dark"]) { /* ライトの値 */ }
}

:root[data-theme="light"] { /* ライトの値 */ }
```

3つのセレクタが必要な理由:

- `@media` だけだと手動でダークに固定できない
- `[data-theme]` だけだと初回起動時（属性が未設定）に OS 設定を無視する
- `:not([data-theme="dark"])` で、手動ダーク指定が OS のライト設定に
  上書きされるのを防ぐ

ライトの値は2箇所に書くことになるので、**CSS カスタムプロパティの定義を
1箇所にまとめ、両方のセレクタから同じ値を書く**。トークン以外の場所に
色を直接書かない（`docs/ui.md` の方針を維持）。

## 3. localStorage の使用を許可する（規約の変更）

`docs/data-model.md` 第7節は「localStorage を設定値のキャッシュにも使わない」と
書いているが、**テーマの値に限って例外とする**。

理由は、IndexedDB の読み取りが非同期であるため、DB から値を読んでから
テーマを当てると、最初の1フレームだけ誤ったテーマが描画されるからです。
アプリを開くたびに画面が白く光る、あるいは黒く光る挙動になります。

元の禁止理由は「保存先を1つにして、ITP に消されるときは全部消えるようにする」
ことでしたが、テーマは以下を満たすため問題になりません。

- IndexedDB が正で、localStorage は表示を先行させるためのキャッシュにすぎない
- 失われても、DB から読み直せば復元できる
- 失われた場合の被害は「初回描画の1フレームだけ既定テーマになる」こと

**この例外はテーマの値のみに適用する。** 他の設定値やトレーニングデータを
localStorage に置くことは引き続き禁止。

### 実装

`index.html` の `<head>` 内、CSS の読み込みより前に同期スクリプトを置く。

```html
<script>
  try {
    var t = localStorage.getItem('gym-log-theme');
    if (t === 'dark' || t === 'light') {
      document.documentElement.setAttribute('data-theme', t);
    }
  } catch (e) {
    // プライベートブラウズ等で localStorage が使えない場合は
    // OS 設定に従う。実害がないため何もしない。
  }
</script>
```

- これは `AGENTS.md` の「グローバル変数を作らない」「ESM のみ」の例外とする。
  モジュールは defer されるため、描画前に実行できない。
- 設定変更時は IndexedDB（正）と localStorage（キャッシュ）の両方に書く。
- 起動後、DB から読んだ値と localStorage が食い違っていたら DB を優先し、
  localStorage を上書きする。

## 4. ライトのトークン

ダークがジムのマシン（炭色のフレーム、スチール、真鍮のピン）から引いたのに対し、
ライトは同じ場所の白い壁とコンクリートの床から引く。単純な色の反転はしない。

```css
/* ライト */
--bg:        #F1F3F4;  /* コンクリートの床 */
--surface:   #FFFFFF;  /* 壁 */
--surface-2: #E7EAEB;  /* 押し込み面・入力欄 */
--line:      #D5DADC;
--text:      #16191B;  /* ダークの --bg をそのまま文字色に使う */
--muted:     #5C676D;
--steel:     #566A74;
--danger:    #9E3A30;

--brass:      #C9992F;  /* 塗り。ダークと同じ */
--brass-text: #86660F;  /* 文字・アイコン・罫線用。ライトのみ暗くする */
```

### `--brass-text` を分ける理由

`#C9992F` を白背景（`#FFFFFF`）に文字として置くとコントラスト比が 3:1 を下回り、
15px 前後の文字が読めなくなります。塗り（ボタンの背景、ドット、選択中の枠）は
そのままで問題ないので、**文字とアイコンに使う分だけ別トークンにします。**

ダークテーマでは `--brass-text` は `--brass` と同じ値（`#C9992F`）にする。
コードの分岐を増やさないため、両テーマで同じトークン名を使う。

### 使い分け

| 用途 | ダーク | ライト |
| --- | --- | --- |
| 主ボタンの背景 | `--brass` | `--brass` |
| 主ボタンの文字 | `#16191B` | `#16191B` |
| 選択中のタブ、自己ベストの印、休憩の経過時間 | `--brass` | `--brass-text` |
| ミニバーの丸 | `--brass` | `--brass` |
| 選択中のセグメントの枠線 | `--brass` | `--brass-text` |

## 5. ライトでの構造の作り方

ダークは `--bg` < `--surface` < `--surface-2` の順に明るくして階層を作っている。
ライトでは**この順序が逆になる**ので、そのままの設計では階層が壊れる。

- `--bg`（グレー）の上に `--surface`（白）を置き、カードが浮いて見えるようにする。
- 入力欄などの押し込み面は `--surface-2`（グレー）で沈ませる。
- 影は引き続き使わない。明度差と `--line` の罫線で構造を作る。

ダークで「明るいほど手前」だったのが、ライトでは「白いほど手前、
グレーほど奥または沈んだ面」になる。どちらも一貫していればよい。

## 6. ステータスバーの色

iPhone のホーム画面から起動したとき、画面上端のステータスバー周辺は
`theme-color` に従う。ここが切り替わらないと、アプリだけテーマが変わって
上端だけ取り残されます。

```html
<meta name="theme-color" content="#16191B" media="(prefers-color-scheme: dark)">
<meta name="theme-color" content="#F1F3F4" media="(prefers-color-scheme: light)">
```

手動でモードを固定した場合は `media` 属性付きの指定では追従しないので、
テーマ適用時に JavaScript で `theme-color` の `content` を書き換える。

```js
// media 属性のない <meta name="theme-color"> を1つ用意し、その content を更新する
```

## 7. 切り替え時の挙動

- **トランジションを付けない。** 全要素の背景色を同時に補間すると描画が重くなり、
  切り替えがもたついて見える。即座に切り替える。
- 切り替え後に再描画やリロードをしない。CSS 変数の変更だけで完結させる。
- 開いているシートやダイアログも同時に切り替わること。
