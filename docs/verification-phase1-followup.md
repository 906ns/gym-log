# 1-1追撃: 連続記録時の入力位置

## 変更

- `js/views/session.js`: 通常配置の入力パネルを、種目名・推定1RMの後、自己ベスト・前回・今日の一覧より前へ移動。stickyは再導入していない。参照先のない `--rest-offset` の設定と毎秒の `getBoundingClientRect()` を削除。
- `sw.js` / `js/views/settings.js`: キャッシュ名を `gym-log-glass-5` に統一。
- 本文書: 実測結果を記録。

データモデル、記録処理、前回値の転記処理、休憩時間の計算は変更していない。

## 確認方法

ローカル静的サーバーの `/gym-log/` をChromiumで開き、viewportを390×664に設定。検証専用のオリジンに前回3セット（60×10、65×8、70×6＋メモ）と今日0セットを作成し、チェストプレスを開いた。以下はCSSピクセルでの `getBoundingClientRect()` の実測値。

### B: スクロールなしの連続記録

クリック座標を指定して3回記録し、ブラウザの自動スクロールに依存しないことも確認。各記録の完了後に測定。

| 今日のセット数 | 重量入力欄 上端〜下端 | 記録ボタン 上端〜下端 | session-scroll.scrollTop |
| --- | --- | --- | --- |
| 0 | 262〜326 | 466〜522 | 0 |
| 1 | 300.5〜364.5 | 504.5〜560.5 | 0 |
| 2 | 300.5〜364.5 | 504.5〜560.5 | 0 |
| 3 | 300.5〜364.5 | 504.5〜560.5 | 0 |

1セット目で推定1RM行が現れるため38.5px下がるが、以後は動かない。休憩フッターはY=599〜664、記録ボタン下端との間隔は38.5px。入力欄と記録ボタンは全段階で完全に画面内にある。

### A: 前回3行＋今日3行の同時表示

連続記録の確認後、一覧へスクロール（scrollTop=527）して6行を同時に表示し、スクリーンショットも目視確認した。

| 対象 | 上端〜下端 |
| --- | --- |
| 入力パネル | -239.5〜46.5 |
| 前回1行目 | 139.5〜187.5 |
| 前回2行目 | 187.5〜235.5 |
| 前回3行目（メモあり） | 235.5〜283.5 |
| 今日1行目 | 310.5〜364.02 |
| 今日2行目 | 364.02〜417.55 |
| 今日3行目 | 417.55〜471.07 |
| 休憩フッター | 599〜664 |

6行それぞれと入力パネル・休憩フッターの重なりは0px。6行すべてが画面内にあり、前回のメモも確認できた。入力時と一覧確認時はスクロール位置が異なる。
